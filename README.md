# BOSS投递助手

> BOSS直聘高效投递工具：AI 智能判断岗位 + 批量投递 + 提示词可自定义
>
> **作者：wok** ｜ **当前版本：v2.4.0** ｜ [更新日志](CHANGELOG.md) ｜ [Bug 修复报告](BUGFIX-REPORT.md)

## 功能

- 🤖 **AI 智能判断** — 逐个打开岗位详情，把「岗位要求 + 你的简历 + 你写的要求」交给 AI，
  由它决定这个岗位投还是不投，并把判定理由写进日志
- 📝 **自然语言要求** — 在提示词编辑器里直接写（"只投杭州上海""不接受外包外派"），
  不用再拼关键词
- 🧩 **提示词可自定义** — 设置 →「投递提示词」→「编辑提示词」打开编辑器：判定规则、简历、
  投递要求都直接写在里面。`{jobTitle}`、`{jobDescription}` 两处会被自动换成当前岗位的信息。
  JSON 输出格式固定在 system 消息里，改不坏
- ⚙ **API 配置** — 兼容 OpenAI 协议（DeepSeek / 通义 / OpenAI / 各类中转站），带「测试连接」
- ▶ **批量投递** — 滚动收集岗位，逐个交给 AI 判定，通过的自动沟通
- 🔁 **聊天页自动轮询** — 从会话列表第一条开始，逐条打开处理，到最后一条自动停止；
  不再只看顶部一条
- 📊 **运行统计** — 岗位列表页实时显示已沟通 / 已跳过 / 失败

## 安装

1. 安装 [Tampermonkey](https://www.tampermonkey.net/) 浏览器扩展（Chrome / Edge 均可）
2. 打开 Tampermonkey → **添加新脚本**
3. 粘贴 `boss-quick-apply.user.js` 全部内容 → `Ctrl + S` 保存
4. 打开 BOSS 直聘职位列表页：**https://www.zhipin.com/web/geek/jobs**
5. 页面右侧出现蓝色面板即安装成功（若未出现，刷新一次页面）

## 使用

1. 在 BOSS 上正常搜索、筛选出你想要的岗位列表
2. 设置 ⚙ → 顶部 **AI API 配置**：填 **API 地址 / API Key / 模型** → 点「测试连接」确认可用
3. 设置 ⚙ → **投递提示词** →「编辑提示词」：在弹窗里写判定要用的素材。
   默认正文已经分好小节、开箱可用，你只需要往 `【我的简历】`、`【我的投递要求】`
   两个小节里填内容（其余规则段想改就直接改）。
   投递要求用自然语言写，例如：

   ```
   只投杭州或上海的岗位；
   期望薪资 15k 以上；
   技术栈以后端 Go / Python 为主，不接受纯外包、外派；
   公司规模 50 人以上的自研团队优先。
   ```

4. 点 **开始投递**。脚本会滚动收集岗位，然后逐个：打开详情 → 抽取岗位要求 →
   连同简历和要求交给 AI 判定 → 判定通过才点「立即沟通」
   （第一条消息由 BOSS 用它自己的「打招呼语」发出）。

日志里每个岗位都会说明为什么投、为什么不投：

```
[3/20] 后端开发工程师 ✅ 通过：技术栈与经验匹配
[4/20] 销售代表     ❌ 跳过：销售岗不符合投递要求
```

> **判定失败一律跳过**：没配 API Key、请求失败、模型返回格式异常，都按「不投」处理。
> 启动前会先检查 API Key，缺了会直接拒绝开始。
>
> **成本提示**：AI 每个岗位会被调用一次。想省 token 就先把 BOSS 侧的搜索条件收窄，
> 让列表里的岗位本身就足够对口。
>
> 为了账号安全，建议在设置中把「投递间隔」保持在 2500ms 以上、「单次投递上限」控制在 50 以内。

### 打招呼语说明

设置 → **打招呼设置**里的「打招呼列表」是**两段式**的：

- **第 1 行**：填你在 BOSS 设置页里配置的**网页自动打招呼语**。
  点「立即沟通」时，BOSS 会先把这句发出去。
- **第 2 行及以后**：脚本要接着发送的消息。

聊天页处理一个首次沟通的会话时，会检查**最后一条我方消息**是否与第 1 行一致：

- 一致 → 说明这次沟通是网页发起的，脚本只发第 2 行及以后，第 1 行不重复发送；
- 不一致 / 第 1 行空着 → 什么都不发，也不记账（避免对旧会话或手动沟通插话）。

想换招呼语内容，请同时修改 **BOSS 设置页 → 打招呼语** 和列表第 1 行，保持两边一致。
职位列表页本身没有可写入的 IM 输入框，脚本不会在投递流程里直接发招呼语。

> **交换联系方式卡片默认不自动同意**：HR 发来交换卡片时，脚本只会记一行日志，
> 不会替你点「同意」——这等于把联系方式交给对方。需要自动同意时，到
> 设置 → **其他** →「自动同意交换」显式开启。

### 聊天页：仅新消息 vs 自动轮询

打开 **https://www.zhipin.com/web/geek/chat**，面板里可以选沟通模式：

- **仅新消息**：每秒检查会话列表最上面一条；有变化才处理。适合只接新会话。
- **自动轮询**：每 2.5 秒推进一次，从会话列表第一条开始，逐条打开、处理，
  到最后一条结束并**自动停止**：
  - 遍历顺序来自页面里的 `chatStore`，启动时做一次快照；
  - 每条会话只打开一次；
  - **打开会话即标为已读**；只有「最后一条我方消息 == 打招呼列表第 1 行」的会话
    才会收到第 2 行及以后的后续消息（首次沟通没有开关；不一致的不发也不记账）。

> 自动轮询依赖页面全局 `chatStore`；
> 拿不到时会自动回退成「只看顶部会话」。
> 实机结构见 [`zhipin-chat-probe.md`](zhipin-chat-probe.md)，
> 执行细节见 [`CHAT-ASSISTANT-LOGIC.md`](CHAT-ASSISTANT-LOGIC.md)。

> 身份判据已从「名字-公司」升级为 BOSS 的稳定 `uid`，旧账本仍兼容。
> 自动轮询依赖页面全局 `chatStore`；拿不到时会自动回退成「只看顶部会话」。
> 实机结构见 [`zhipin-chat-probe.md`](zhipin-chat-probe.md)，
> 执行细节见 [`CHAT-ASSISTANT-LOGIC.md`](CHAT-ASSISTANT-LOGIC.md)。

## 常见问题

| 现象                          | 处理                                                                                                                                                             |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 面板不出现                    | 确认地址是职位列表页；刚安装脚本请刷新页面（Ctrl + F5）                                                                                                          |
| 点「开始投递」没反应          | 日志会说明原因。最常见的是没配 API Key                                                                                                                           |
| 所有岗位都被跳过              | 看日志里的 ❌ 理由。若全是「AI 判定失败」，去设置里点「测试连接」排查 Key / 余额 / 地址                                                                          |
| 日志出现「⚠️ 没抓到岗位要求」 | 下一行的「诊断」会说明接口和详情区分别看到了什么。把这两行发到 issue 即可定位                                                                                    |
| 找不到「立即沟通」按钮        | 确认已在 BOSS 设置页开启「打招呼语」                                                                                                                             |
| 只扫描不投递                  | v2.1.0 已修复；另外请确认已在 BOSS 设置页开启「打招呼语」                                                                                                        |
| 日志提示「占位符没法替换」    | 主提示词里的 `{xxx}` 不是可用变量（只有 `{jobTitle}` / `{jobDescription}` 会被替换），<br>它会原样发给 AI。多半是从旧版本带过来的 `{resume}`，改成直接写内容即可 |
| 想恢复面板                    | 点左下角圆形图标，或按 F5 刷新                                                                                                                                   |

## 开发

源码在 `src/`（真正的 ES module），由 esbuild 打包成根目录的
`boss-quick-apply.user.js`。

> ⚠️ 构建产物**需要提交**——用户通过它安装和自动更新，路径不能改。
> 对使用者而言没有任何变化，安装步骤同上。

```bash
npm install
npm run build         # src/ → boss-quick-apply.user.js
npm run check         # 构建 + 语法检查
npm test              # 冒烟 + 投递流程 + 设置/提示词 + 聊天页打招呼 + 自动轮询
npm run test:flow     # 只跑投递流程（断言 AI 到底收到了什么）
npm run test:settings # 只跑设置与提示词编辑器
npm run test:chat     # 只跑聊天页（打招呼/卡片 + 自动轮询）
npm run deps          # 打印 ES module 依赖图与环
npm run format:check  # 格式检查
```

**改代码前请先读 [`src/README.md`](src/README.md)**，里面写了四条硬规则：

1. 启动必须由 `main.js` 的 `start()` 触发，不能在模块顶层调用 —— 模块图里有
   **一个 6 模块主环**（`03/04/05/07/08/09`）和一个 `13↔15` 小环，顶层调用会在
   依赖未就绪时执行（重构时真实踩过：`StatePersistence is undefined`，脚本静默失效）
2. import 顺序有意义，但环内的求值顺序不要依赖
3. 模板字符串里的空白是内容，不是排版
4. 别在模块顶层加有副作用的初始化

以及几个必须知道的隐形不变量（`state.settings === settings` 的对象同一性、
`settings` 上的 getter 兼容层、猴补丁只打一次、打包器会 tree-shake 未引用的导出）。

### 重构后如何证明"没改坏"

模块化之后，"逐字节相同"和"AST 等价"都不再适用（打包器会重排、重命名、常量折叠）。
改用**行为比对**：把两个版本分别加载进同一份页面 fixture，比对脚本产生的 DOM、
猴补丁状态、全局泄漏和未捕获错误。

```bash
git show HEAD:boss-quick-apply.user.js > /tmp/old.js
npm run verify -- /tmp/old.js boss-quick-apply.user.js
```

`tools/ast-equivalent.js`（AST 等价 + 字面量逐条比对）在纯格式化/搬家类改动中仍然好用，
也保留在 `tools/` 里。
